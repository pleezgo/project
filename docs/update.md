# Оновлення системи

## Підготовка до оновлення

1. Створи резервну копію бази даних:
```bash
pg_dump -U your_username your_database_name > backup.sql
```
2. Перевір сумісність нової версії з поточними залежностями (`package.json`)
3. Заплануй час простою - рекомендовано проводити оновлення в нічний час з мінімальним навантаженням. Повідом користувачів якщо оновлення потребує зупинки сервісу.

## Процес оновлення

1. Зупини backend і frontend сервіси через інтерфейс платформи або process manager.

2. Отримай новий код:
```bash
git pull origin main
```

3. Оновити залежності:
```bash
cd backend
npm install
cd ../frontend
npm install
```

4. Міграція даних - у даному проекті не потрібна, таблиці створюються автоматично при запуску backend. Якщо в майбутньому зміниться схема бази даних - виконай відповідні міграції вручну перед запуском.

5. Оновлення конфігурацій - якщо в новій версії з'явились нові змінні оточення - додай їх у `backend/.env` відповідно до `backend/.env.example`, для frontend - встанови змінні оточення на сервері або платформі розгортання.

6. Запусти backend:
```bash
cd backend
npm start
```
Запусти frontend:
```bash
cd frontend
npm run build
npm run preview
```
### Автоматизація запуску

Для зручності можна використати готові скрипти з папки `docs/scripts/`:

- Linux: `bash docs/scripts/prod.sh`
- Windows: `docs\scripts\prod.bat`

## Перевірка після оновлення

1. Відкрий URL frontend - має завантажитись застосунок
2. Зареєструйся або увійди - підтверджує що backend і PostgreSQL працюють
3. Знайди продукт через пошук - підтверджує що USDA API ключ валідний

## Rollback

1. Відкотись до попередньої версії коду:
```bash
git log --oneline
git checkout <commit_hash>
```
2. Відновити базу даних з резервної копії:
```bash
psql -U your_username your_database_name < backup.sql
```
3. Перезапусти сервіси відповідно до інструкції розгортання
