# Архітектура проєкту

## Загальна структура

Проєкт має клієнт-серверну архітектуру і складається з трьох основних частин:

- `frontend` - клієнтський застосунок на React + Vite
- `backend` - серверний застосунок на Node.js + Express
- `PostgreSQL` - база даних для збереження користувачів, профілів і записів харчування

## Основний потік взаємодії

1. Користувач взаємодіє з інтерфейсом у `frontend`.
2. `frontend` викликає методи з `src/api/api.js`.
3. API-запити надсилаються на `backend` до маршрутів `/api/...`.
4. На захищених маршрутах виконується middleware автентифікації `auth`.
5. Контролери обробляють запит, звертаються до PostgreSQL і формують JSON-відповідь.
6. `frontend` отримує дані й оновлює стан сторінок та компонентів.

## Архітектура frontend

### Основні модулі

- `src/App.jsx` - кореневий компонент, маршрутизація та розподіл маршрутів
- `src/context/AuthContext.jsx` - керування станом автентифікації користувача
- `src/api/api.js` -  виклики backend API
- `src/components/Layout.jsx` - базовий макет авторизованої частини застосунку
- `src/pages/*` - сторінки застосунку (`Dashboard`, `Food`, `Profile`, `Login`, `Register`)

### Принцип роботи frontend

Frontend працює з Backend, та не працює безпосередньо з БД. Уся взаємодія з даними відбувається через backend API. JWT-токен зберігається в `localStorage` і додається до запитів через заголовок `Authorization: Bearer`.

## Архітектура backend

### Основні модулі

- `src/server.js` - запуск Express-сервера та ініціалізація застосунку
- `src/routes/index.js` - опис API-маршрутів
- `src/middleware/auth.js` - перевірка JWT-токена
- `src/controllers/authController.js` - реєстрація та вхід користувача
- `src/controllers/profileController.js` - робота з профілем користувача
- `src/controllers/foodController.js` - робота із записами харчування, власними продуктами, статистикою та dashboard
- `src/config/db.js` - підключення до PostgreSQL
- `src/config/schema.js` - створення таблиць бази даних під час запуску

### Принцип роботи backend

Backend побудований за модульним принципом:
- `routes` визначають точки входу API
- `middleware` виконує перевірки до виклику контролера
- `controllers` контролери
- `config` відповідає за налаштування

## Взаємодія frontend і backend

Frontend використовує такі основні API:
- `POST /auth/register`
- `POST /auth/login`
- `GET /profile`
- `PUT /profile`
- `GET /dashboard`
- `GET /food`
- `GET /food/stats`
- `GET /food/search`
- `GET /food/custom`
- `POST /food`
- `POST /food/custom`
- `DELETE /food/:id`

Таким чином, frontend відповідає за відображення і взаємодію з користувачем, а backend - за автентифікацію, обробку запитів, доступ до даних і бізнес-логіку.

## Основні архітектурні рішення

- Розділення frontend і backend. Таке розділення дозволяє незалежно розвивати клієнтську і серверну частини, а також спрощує підтримку коду.

- Використання JWT: використовується для автентифікації користувача на захищених маршрутах. Це дозволяє frontend зберігати токен і передавати його в кожному запиті без серверної сесії.

- Усі HTTP-запити винесені в `src/api/api.js`, що спрощує підтримку та зміну способу взаємодії з backend.

- Контролери, маршрути, middleware і конфігурація розділені за відповідальністю, що полегшує супровід і документування.

## Дані, що зберігаються в базі

Основні таблиці:
- `users`
- `user_profiles`
- `food_logs`
- `custom_foods`

Вони покривають автентифікацію, профіль користувача, записи харчування та власні продукти.

- пояснення архітектурних рішень
- підтримки узгодженого стилю розробки
