# Резервне копіювання

## Стратегія резервного копіювання

Проєкт використовує PostgreSQL як єдине сховище даних. Файлове сховище відсутнє - всі дані зберігаються в базі даних.

### Типи резервних копій

- **Повна копія** - повний дамп бази даних через `pg_dump`. Використовується як основний тип резервного копіювання.
- **Інкрементальна копія** - не застосовується через невеликий обсяг даних.
- **Диференціальна копія** - не застосовується.

### Частота створення копій

- Повна резервна копія - щодня, оскільки користувачі щоденно вносять записи до щоденників
- Рекомендований час - нічний період з мінімальним навантаженням

### Зберігання та ротація

- Зберігати копії протягом 7 днів
- Видаляти копії старші 7 днів автоматично
- Зберігати копії на окремому сервері або хмарному сховищі

## Процедура резервного копіювання

### База даних та конфігурація

Для створення резервної копії використовуй готовий скрипт:

**Linux/Mac:**
```bash
bash docs/scripts/backup.sh
```

**Windows:**
```bat
docs\scripts\backup.bat
```

Або вручну (перевірте що створена папка backup):
```bash
pg_dump -U your_username your_database_name > backup/backup_$(date +%Y%m%d).sql
cp backend/.env backup/.env_$(date +%Y%m%d)
```

### Користувацькі дані

Всі користувацькі дані зберігаються в PostgreSQL і включаються до резервної копії бази даних автоматично.

### Логи системи

Логи виводяться в стандартний вивід процесу Node.js. Для збереження логів у файл (перевірте що створена папка logs):
```bash
npm start > logs/app.log 2>&1
```

## Перевірка цілісності резервних копій

1. Перевір що файли резервної копії не порожні:
```bash
ls -lah backup/
```

2. Перевір що файл не пошкоджений - спробуй відновити на тестовій базі даних.
```bash
psql -U your_username -d test_restore -f backup/backup_YYYYMMDD.sql
```

## Автоматизація резервного копіювання

Скрипти автоматично:
- Створюють папку `backup/` якщо не існує
- Зберігають дамп бази даних з датою в назві
- Копіюють файл конфігурації `.env`
- Видаляють копії старші 7 днів

Для автоматичного запуску щодня додай до планувальника:

**Linux/Mac (crontab):**
```
0 3 * * * bash /path/to/project/docs/scripts/backup.sh
```

Для редагування або видалення:
```bash
crontab -e
```

**Windows (Планувальник завдань):**
Додай `docs\scripts\backup.bat` до планувальника завдань для щоденного запуску, наприклад в 3:00.

## Процедура відновлення

### Повне відновлення системи

1. Зупини backend сервіс
2. Відновити базу даних з резервної копії:
```bash
psql -U your_username -d your_database_name -f backup/backup_YYYYMMDD.sql
```
3. Відновити файл конфігурації:
```bash
cp backup/.env_YYYYMMDD backend/.env
```
4. Запусти backend і frontend

### Вибіркове відновлення даних
Бінарний формат створюється окремо за потреби і не входить в регулярне резервне копіювання.
Для вибіркового відновлення окремої таблиці створи бекап в бінарному форматі:
```bash
pg_dump -U your_username -F c your_database_name > backup.dump
```

Відновлення окремої таблиці:
```bash
pg_restore -U your_username -d your_database_name -t table_name backup.dump
```

### Тестування відновлення
1. Створи тестову базу даних:
```bash
psql -U your_username -c "CREATE DATABASE test_restore;"
```
2. Відновити копію на тестову базу:
```bash
psql -U your_username -d test_restore -f backup/backup_YYYYMMDD.sql
```
3. Перевір що таблиці є:
```bash
psql -U your_username -d test_restore -c "\dt"
```
4. Видали тестову базу після перевірки:
```bash
psql -U your_username -c "DROP DATABASE test_restore;"
```
